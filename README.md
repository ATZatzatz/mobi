# 墨笔

一个简洁、稳定、可自由修改的 Markdown 长文写作工具（内部代码名仍是 MobiWriter）。

做它的初衷是替代 WonderPen 这类付费闭源写作软件，同时把「文稿是我的普通文件，不是被锁在某个软件数据库里」这件事放在第一位。

- 界面取向：WonderPen / Ulysses 那种安静的三栏写作台，图标化顶栏，纸感配色，正文居中排版。
- 数据取向：文稿就是磁盘上的 `.md` 文件，目录树的层级 = 真实的文件夹层级。

---

## 功能

| 需求 | 实现 |
| --- | --- |
| Markdown 编辑器 | CodeMirror 6 源码编辑 + markdown-it 实时预览（默认收起，`Ctrl+Shift+P` 唤出），语法高亮、查找替换、撤销重做 |
| 简洁 | 单窗口三栏，无插件系统、无数据库、无私有格式，全部源码 26 个文件 |
| 稳定可靠 | 原子写入、自动保存、快照、回收站、外部改动冲突提示、退出前强制落盘 |
| 导出 PDF | Chromium `printToPDF`，A4/A5/A3/Letter、页边距、页码、打印样式表，中文字体已嵌入 |
| 嵌套文件列表 | 懒加载文件树，支持新建 / 重命名 / 拖动移动 / 删除到回收站 / 右键菜单 / 一键全部展开 / 批量导入 Markdown |
| 全局搜索 | 整个文档库搜索，可切换「只看文件名」或「文件名 + 正文」，结果可点击跳转到具体行并选中 |
| 查找替换 | 文稿内查找替换（`Ctrl+F` / `Ctrl+H`），支持区分大小写、正则、全词匹配、全部替换 |
| 一键备份 | 整个文档库复制成一份带时间戳的快照，可以放到网盘同步目录 |
| 排版可调 | 编辑区行距 / 预览与导出行距 / 段后距都能调，带一键恢复默认 |
| 阅读模式 | 打开预览时可选隐藏源代码，只留渲染后的正文 |
| 分页预览 | 预览可按纸张（A4 等）分页显示，**导出 PDF 用的是同一份分页结果**，两边完全一致 |
| 面板开关 | 标题栏右侧像 VS Code 一样开关左栏（文稿树）/ 右栏（预览）/ 下栏（状态栏） |
| 界面缩放 | `Ctrl+=` 放大、`Ctrl+-` 缩小、`Ctrl+0` 恢复，设置面板里也有按钮 |
| 标记语法 | 正文里用 `【】` 框起来的文字按指定颜色显示，颜色可在设置里改 |

其他：深浅主题、专注模式（含打字机滚动）、字数统计、最近打开的文稿库、图片与链接的相对路径解析。

## 技术栈

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 外壳 | Electron 44 | 唯一能白拿 Chromium `printToPDF` 的方案：PDF 导出零外部依赖、跨平台样式一致 |
| 编辑器 | CodeMirror 6 | 中文输入法（IME）、撤销栈、超长文档视口渲染这三件事自己写必翻车 |
| 渲染 | markdown-it + highlight.js | 成熟、无状态、好替换；`html: false` 不允许文稿塞原始 HTML |
| 构建 | electron-vite + Vite 7 + TypeScript 5.9 | 主进程 / preload / 渲染层三段式构建，渲染层有热更新 |
| 界面 | 原生 TypeScript + CSS 变量 | 不引 UI 框架。界面只负责画树和工具栏，少一层抽象就少一类稳定性问题 |
| 字体 | MiSans（随包分发） | 见下方「字体」一节 |

## 文档库

**所有文稿都放在同一个文件夹里，这个文件夹叫「文档库」，启动就自动打开，不需要每次选。**

- 默认位置：`我的文档\MobiWriter`（`C:\Users\<你>\Documents\MobiWriter`）。首次启动会自动创建，并放一篇《欢迎使用.md》当说明
- 这个位置记在设置里，下次启动直接打开；换位置：点顶栏最左边那个文件夹图标
- 文稿树最上层直接就是文档库里的文件夹和文稿，层级 = 磁盘上真实的文件夹层级
- 树上**不显示 `.md` 后缀**，只显示文稿名；悬停能看到完整路径。重命名时后缀会自动补回，不用担心改完名字文稿从树上消失
- **拖动**：把文稿或文件夹拖到别的文件夹上就完成了移动；拖到空白处 = 移到文档库最外层；悬停在收起的文件夹上会自动展开；靠近上下边缘会自动滚动；`Esc` 取消
- **批量导入**：点顶栏的导入图标（或右键文件夹 → 导入 Markdown 文件…），可以一次选多个 `.md` / `.markdown` / `.mdx` / `.txt` 复制进文档库。只复制不动原文件，重名自动加序号，**绝不覆盖已有文稿**
- 想一眼看清整个结构：点侧栏左上角的「一键展开」按钮，整个文档库会一次性全部展开（再点一次折叠）。超过 1200 个文件夹会停下并提示，避免超大文档库把界面拖死
- 根节点不能重命名/删除（它就是文件夹本身）；右键可以「复制文档库路径」或「在资源管理器中打开」
- 文档库目录如果被删了或盘符没挂载，启动时会先尝试原地重建，重建不了才退回默认位置，并写进日志

文稿始终是普通 `.md` 文件，不打开这个程序也能读、能 git 管、能整包拷走。

## 备份

设置面板底部（或菜单「文件 → 备份整个文档库…」）有「立即备份」。

- 备份就是**把文档库整个复制**到你选的位置，新建一个 `<文档库名>-备份-20260914-2130` 这样的文件夹
- 刻意不做增量、不打包压缩：备份出来的东西是**人能直接打开、网盘能直接同步**的普通文件夹，而不是只有本程序认识的归档文件
- 备份位置会记住，下次默认还是那里；放在网盘同步目录里就等于云端备份
- **不包含** `.mobiwriter`（回收站和历史快照），那是内部数据
- 文稿里引用的图片等非 md 文件也会一起备份
- 会拦住「备份到文档库自己内部」这种会无限递归的操作

## 排版与阅读模式

设置面板「排版」一节：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 编辑区行距 | 2 | 只影响写作用的源码视图 |
| 预览与导出行距 | 1.85 | 预览和导出 PDF 共用，导出时会写进打印文档 |
| 段后距（em） | 1 | **只作用于段落和引用；列表项不吃这个间距**，保持紧凑 |

旁边有「恢复默认行距 / 段后」一键回到上表的值。

「写作」一节里的**预览时隐藏源代码**打开后，切到预览就是纯阅读模式（编辑区收起，预览铺满），关掉预览即恢复。

## 分页预览与导出

设置 →「写作」→ **预览分页显示（按纸张）**。开启后预览会按「纸张大小」把正文切成一张张纸（A4/A5/A3/Letter），带页边距和页脚页码；导出的 PDF 用**同一份分页结果**，所以预览什么样、导出来就是什么样。

为什么能保证一致：浏览器在屏幕上不翻页，而打印时是 Chromium 按它自己的算法断页，两边的断点不可能天然一致。所以这里**自己按块边界分页**（`src/renderer/src/paginate.ts`），再把同一份分页 HTML 分别交给预览和打印：

- 分页粒度是块级元素（段落、标题、列表、代码块），宁可一页少放几行，也不把一行劈开
- 万一某个块本身比一页还高（比如超长代码块），让它单独占一页，溢出部分交给打印引擎续页，**绝不裁掉内容**
- 页脚页码由页面自己画（分页模式下会关掉 Chromium 的页眉页脚，页边距也交给页面自己，避免被挤两次）

分页要离屏量高度，比普通预览慢，所以分页模式下的预览刷新延迟会放宽到 520ms。

## 自定义语法：居中标题

标准 Markdown 没有居中，这里加了一条：

```markdown
#@ 居中一级标题
##@ 居中二级标题
###@ 居中三级标题
```

`#@` 前面有几个 `#` 就是几级标题，最多六级（和标准 ATX 标题一致）。
编辑器里这一行会直接居中显示、`#@` 标记显示为灰色；预览和导出 PDF 里是真居中，并且不带标题下划线。

实现分两处，改的时候别漏：

| 位置 | 作用 |
| --- | --- |
| `src/renderer/src/centered-heading.ts` 的 `centeredHeading()` | markdown-it 块级规则，产出 `<h1 class="md-center">` |
| 同文件的 `centeredHeadingLines()` | CodeMirror 行装饰，让源码视图里也居中、标记灰显 |

样式在 `preview.css` 的 `.markdown-body .md-center`。围栏代码块里的 `#@` 不会被误伤。

顺带一提：渲染出来的**有序列表用中文顿号序号**（`1、2、3、`），靠 `preview.css` 里的 `@counter-style cjk-ordered` 实现。用 `@counter-style` 而不是 CSS 计数器，是为了让 `<ol start="3">` 依然有效、嵌套列表也能各自重新计数。

## 搜索（集成在文件列表里）

搜索框就在左栏文件列表的顶部（顶栏放大镜图标或 `Ctrl+Shift+F` 聚焦）。输入关键词后，**文件树会切换成结果列表**：

- **两种范围**：`名`（只看文稿名，几乎瞬时，完全不读文件内容）/ `名+文`（连正文一起搜）；`Aa` 切换区分大小写
- 结果里每篇文稿一行，正文命中的行挂在下面，**点哪一行就跳到那一行并选中命中文字**
- 清空关键词（点 × 或按 `Esc`）立刻回到文件树

实现要点（`src/main/search.ts`）：

- **不建索引**。文稿是普通文件，用户随时会在外部改动，索引一致性维护成本远高于收益；写作库一般几百到几千个文件，直接扫一遍够快（实测 3 篇 1ms，几百篇几十毫秒）
- 保留上限防止卡死：最多扫 5000 个文件、**单个文件超过 2MB 不搜正文**、最多 200 个命中文件、每个文件最多列 6 行、单行显示截断到 160 字
- 支持取消：每次输入都带自增序号，主进程发现序号变了立刻收手，过期结果在渲染层直接丢弃

## 切分与合并文稿

**切分**：在正文里右击 → **从光标处切分文件**。光标之前的内容留在原文件，之后的内容另存为 `<原文件名>_被切分.md`，光标停在切分点上。光标两边都得有内容才允许切。

**合并**：在文件列表里 `Ctrl` 点选多篇（`Shift` 框选一段）→ 在选中项上右击 → **合并选中的 N 个文稿…**。合并出的新文件叫 `<第一个文件>_被合并.md`：

- **文件名和内容顺序都按你点选的先后顺序**，不按列表顺序——中文排序下「第二章」会排在「第一章」前面，按列表顺序会跟直觉相反
- 各篇之间空一行拼接
- **原文稿全部保留**，不做删除（怕误操作丢内容；想清理自己去删）
- 新文件放在第一个文稿所在的目录里

**反复调试时不需要打包**，按下面选一种：

| 命令 | 用途 | 耗时 |
| --- | --- | --- |
| `npm run dev` | **改代码时用这个**。渲染层热更新，主进程改动自动重启窗口 | 秒级 |

这三个命令走的都是 `scripts/dev.mjs` 这一层薄启动器，**不是**直接调 electron-vite。原因见下。

## 启动不了？先看这两条

**1. `ELECTRON_RUN_AS_NODE` 被设置了 → 窗口永远不出现**

这个环境变量会让 Electron 退化成纯 Node 运行，不报错、不弹窗，就是没有窗口（某些编辑器 / 终端 / 自动化环境会自动带上它）。

`scripts/dev.mjs` 会在启动前**自动把它从子进程环境里删掉**，所以 `npm run dev` 现在不受它影响。如果你绕过 npm 直接调 electron，就要自己清：

```powershell
$env:ELECTRON_RUN_AS_NODE=""     # PowerShell
set ELECTRON_RUN_AS_NODE=        # cmd
```

**2. 提示「墨笔已经在运行了」→ 单实例锁**

同一时间只允许一个窗口（避免两个进程同时写同一批文稿）。如果之前开的窗口没关干净，`npm run dev` 会弹框告诉你，而**不是静默退出**。卸载或关掉那个窗口再启动即可：

```powershell
Get-Process electron,MobiWriter -ErrorAction SilentlyContinue | Stop-Process -Force
```

注意开发和安装版**共用**同一份设置与锁（数据目录固定在 `%APPDATA%\MobiWriter`），所以装好的墨笔开着时，`npm run dev` 也会被挡住。

改代码 → `npm run dev` 看效果 → 满意了再 `npm run dist` 出安装包，这个顺序就够了，不需要每改一次就打一次包。

首次 `npm install` 会下载 Electron 二进制（约 200MB），`.npmrc` 里已经配好 npmmirror 镜像。

```bash
npm install
npm run dev
```

## 数据放在哪

| 内容 | 位置 |
| --- | --- |
| 文稿 | 你自己选的文件夹，普通 `.md` / `.txt` |
| 回收站 | `<文稿库>/.mobiwriter/trash/`，删除只是移动，附 `.json` 元数据便于还原 |
| 快照 | `<文稿库>/.mobiwriter/history/`，覆盖前留旧版本，同一文件每 5 分钟最多一份，保留 20 份 |
| 设置 | `%APPDATA%/mobiwriter/settings.json` |
| 日志 | `%APPDATA%/mobiwriter/logs/main.log` |

`.mobiwriter` 目录在文件树里是隐藏的，也不会被监听。

## 稳定性设计

「不丢稿」是靠下面这几件事一起保证的，改动代码时请勿破坏：

1. **原子写入**（`src/main/atomic.ts`）
   写同目录临时文件 → `fsync` → `rename` 覆盖。任何时刻断电，目标文件要么是旧内容要么是新内容，不会出现写了一半的文件。Windows 上杀毒软件 / OneDrive 会短暂占用句柄导致 `rename` 报 `EBUSY/EPERM`，这里做指数退避重试，最后兜底为直接覆盖写——宁可牺牲一点原子性，也不能让用户看到「保存失败」。启动时会清扫上次崩溃遗留的 `.tmp` 文件。

2. **自动保存**（`src/renderer/src/main.ts`）
   停止输入 `autosaveMs`（默认 1500ms）后写盘，另有一个最长时间上限，避免用户一直不停手就一直不保存。写盘后只有确认「内容没被继续修改」才清除脏标记，防止把新敲的字判成已保存。切换文稿、导出 PDF、关闭窗口、退出程序前都会先 flush。

3. **外部改动冲突**
   监听器会屏蔽自己写入触发的事件（否则会出现「自己改自己 → 重新加载 → 光标跳走」的死循环）。真正的外部改动：没有未保存内容就静默重载；有未保存内容则弹出横幅，让你选「重新载入磁盘版本 / 用我的覆盖磁盘 / 先不管」；文件被外部删除时提示另存为新文稿。

4. **删除 = 移动**
   删除进回收站，永不真删。

5. **崩溃兜底**
   渲染进程意外退出会记录日志并提示重新加载；未捕获异常写 `main.log`；窗口关闭和退出都被拦截到「先落盘再退出」，最多等 5 秒。

6. **路径安全**
   所有路径都要过 `resolveInside()` 的越界检查，`../` 和绝对路径都会被拒绝；新建 / 重命名会拦截 Windows 保留名、非法字符、结尾点号等。

## 界面与标题栏

窗口用的是**无边框 + 系统窗口按钮覆盖层**（`titleBarStyle: 'hidden'` + `titleBarOverlay`）：

- 原生标题栏被隐藏，顶栏自己画，所以不存在「原生条和自绘条两层颜色对不上」的问题
- 右上角的最小化 / 最大化 / 关闭三个按钮仍由 Windows 绘制，颜色通过 `setTitleBarOverlay` 跟随主题切换
- 原生菜单栏默认收起，按 `Alt` 唤出（避免菜单条再叠一层）
- 顶栏是拖拽区（`-webkit-app-region: drag`），双击可最大化

因此改配色时有一处**必须同时改两个地方**：

| 改什么 | 文件 |
| --- | --- |
| 界面配色 | `src/renderer/src/styles.css` 的 `--topbar-bg` / `--fg` |
| 窗口按钮与窗口底色 | `src/shared/theme.ts` 的 `TITLE_BAR_THEME` / `WINDOW_BACKGROUND` |

**原生菜单栏是固定隐藏的**（`autoHideMenuBar: false` + `setMenuBarVisibility(false)`），
故意不启用「按 Alt 唤出」——不然按住 Alt 做列选择时菜单条会弹出来把客户区挤下去。
应用菜单本身仍然挂在窗口上，所以 `Ctrl+O`、`Ctrl+P` 这些快捷键照常工作；
「打开回收站 / 打开数据目录 / 版本号」这些原本只在菜单里的入口，移到了设置面板底部。

另外 Windows / Linux 下顶栏右侧要为空出来的窗口按钮留位，宽度写在 `styles.css` 的 `html[data-platform='win32'] .topbar` 里（CSS 通过 `preload` 暴露的平台标识来区分系统）。

## 字体

正文、界面、导出 PDF 全部硬编码使用 **MiSans**（小米字体），字体文件随应用分发在 `src/renderer/public/fonts/`，不依赖用户机器上是否安装过：

- `MiSans-Regular.otf` → 字重 400
- `MiSans-Medium.otf` → 字重 500 / 600
- `MiSans-Bold.otf` → 字重 700 / 900

版权归北京小米移动软件有限公司所有，可免费商用。要换字体：替换这三个文件并同步修改 `public/fonts/misans.css`、`styles.css` 里的 `--editor-font`、以及 `src/main/pdf.ts` 里的 `FONT_FILES`（导出窗口是独立页面，必须自己声明一遍 `@font-face`）。

## 标记语法：`【文字】`

正文里用 `【】` 框起来的文字会用指定颜色显示（默认朱砂红，设置 →「排版」→「【标记】文字颜色」可改）：

```markdown
这里有一处【重要】提示。
```

预览、导出 PDF、源码视图三处都会跟着变色。实现分两处（和居中标题同一套路）：

| 位置 | 作用 |
| --- | --- |
| `src/renderer/src/mark-text.ts` 的 `cnMark()` | markdown-it **核心规则**，产出 `<span class="md-mark">` |
| 同文件的 `cnMarkLines()` | CodeMirror mark 装饰，源码视图里也变色 |

**注意**：这里必须用核心规则而不是 inline 规则。markdown-it 的 `text` 规则会把整段普通文字一次吞掉，而 `【` 不在它的默认终止字符表里，inline 规则根本没机会被调用——这一点踩过坑，改的时候别退回去。

## 已知限制

- **预览是整篇重渲染**（输入防抖 140ms，全量 markdown → HTML）。几万字的稿子没问题，50 万字符以上会开始卡，要改就得做增量渲染。
- 编辑器和预览的滚动同步是**按比例映射**，不是按标题精确对齐。
- 放在 OneDrive / 坚果云等同步目录里仍可能产生冲突副本，程序会提示但不会自动合并。
- 快照是「每 5 分钟最多一份」，不是每次保存都留档。
- 还没有全库搜索、大纲 / 卡片、导出 Word / EPUB。
- 单实例锁：同一时间只能开一个窗口。
- 打包默认只配了 Windows NSIS；macOS 需要自行补签名与 notarize 配置。
